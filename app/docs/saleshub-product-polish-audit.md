# SalesHub Product Polish and Consistency Audit

Date: October 19, 2026. Scope: Sales, Sales Management, Support, Marketing, Administration, and executive users working through existing management or Read Only access.

SalesHub already has useful business workflows, shared controls, and good explanations of several difficult concepts. The highest-value polish is to make those capabilities easier to find and interpret: distinguish the history reports by business purpose, remove navigation dead ends, use ordinary language in Administration, and apply existing filter and empty-state patterns consistently. A broad redesign is unnecessary.

This report proposes work. No application wording, schema, migrations, permissions, calculations, workflows, or business data were changed. Nothing was committed, pushed, or deployed. The only repository addition is this report.

## Evidence and review limits

- Inventoried all **131 `page.tsx` files**, including dynamic detail/edit routes, and reviewed copy, shared forms, navigation, filters, historical reporting, and the **24 in-app Help topics**. The coverage appendix distinguishes route inventory from deeper review.
- Checked the running local application at `http://127.0.0.1:3000` with an existing linked Admin identity. Authenticated Dashboard, Accounts, account creation, and Administration requests encountered HTTP 500 before normal page content rendered. Further browser traversal was stopped.
- Confirmed the database has USD active and default, and the currency migration is recorded as completed. The running generated Prisma client does **not** contain `Currency.isDefault`. Its currency read omits that field, and the shared layout then throws `Configure an active default currency.` This is a runtime/client mismatch, not evidence that the currency data needs changing.
- Reviewed eight existing October 18 validation screenshots: Currency Settings and Pipeline Movement History & Outcomes at widths **390, 768, 1024, and 1440 pixels**. These are prior fixture screenshots, not fresh live-page verification. Source review supports the broader responsive findings; rendered fit across the rest of the application remains unverified.
- Browser requests that could mutate data were blocked. Support Inbox and email-attachment retrieval were reviewed in source because opening those screens can record integration attempts or fetch provider data. No imports, captures, syncs, notifications, or maintenance actions were run.
- Cross-role findings use the actual permission, navigation, and Help visibility code. A fresh interactive role matrix was prevented by the layout failure. No Executive role or additional permissions are proposed.

Severity: **High** can materially mislead a business decision, block work, or prevent recovery; **Medium** creates repeated friction or ambiguity; **Low** is localized presentation polish. Effort: **Small** is localized copy or presentation; **Medium** spans shared components or several screens; **Large** changes a reporting/workflow policy or requires substantial historical compatibility work. Estimates are relative, not delivery commitments.

| State | Suggested language | Appropriate action |
| --- | --- | --- |
| No data exists in the accessible scope | “No Support Cases yet.” | New case for writers; explain how cases appear for viewers. |

## Areas that should remain unchanged

- **Currency meaning:** no automatic conversion; unlike currencies stay separate; default changes do not rewrite existing amounts; inactive historical currency remains readable; redundant selectors can remain hidden when there is no meaningful choice.
- **Financial history:** snapshots are immutable evidence; absent captures are not zero; disappearance is not proof of Lost; captured names and values must not be silently replaced by today's names and values.
- **Close timing:** Expected Close Date and Actual Close Date remain distinct. Saved forecast-quarter placement continues to use its existing captured Expected Close Date rule. Closed Won in a snapshot is not booked or recognized revenue.
- **Pipeline reconciliation:** one financial contribution per deal; category transfers can change composition without changing total Pipeline; group lists may overlap and are not additive. Keep warnings near the affected results.
- **Ownership and permissions:** shared visibility is not ownership or edit rights; Contacts follow Account ownership; current role checks and reassignment eligibility remain intact. No extra Executive or Support permissions are proposed.
- **Support email:** Gmail remains the email system of record; SalesHub tracks the Case; logging a response does not send it; attachments are optional; ignore does not delete Gmail mail; incomplete thread windows and failed optional imports stay explicit.
- **Work types:** Activities, Tasks, Notes, and Project Updates have different purposes. Case status changes, Task completion, routing, and Activity logging remain independent where they are independent today.
- **Archive and history:** inactive, archived, closed, resolved, and completed remain distinct states. “Not recorded” remains distinct from “none,” and partial audit coverage must remain visible.
- **Pricing and imports:** retain PE numbers, BXS numbers, SKUs, minimum quantities, approved pricing tiers, source revisions, source evidence, customer applicability, preview/confirm, and the difference between a source name and a resolved CRM link.
- **Marketing consent and influence:** an audience match does not imply marketing consent; campaign influence does not assign revenue credit; duplicate resolution still requires review.
- **Useful existing UI foundations:** keep `PageHeader`, `.field`, button variants, searchable pickers, bounded table scrolling, responsive navigation, current Saved Views privacy, and explicit bulk confirmation. Standardize adoption rather than rebuild the design system.
