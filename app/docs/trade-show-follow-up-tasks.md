# Trade Show follow-up Tasks

When a new Trade Show Lead is imported with BIXOLON Sales routing, or an existing lead changes to that routing or a different Sales rep, the same database transaction creates or updates its follow-up Task. The import continues to skip already imported leads; source refreshes and unchanged assignments do not touch Tasks. No migration backfill runs for historical leads.

The Task is due after the Admin-configured **Trade Show lead follow-up due** number of Monday–Friday business days, using the CRM's America/New_York calendar day. The default is two business days; Admin may set 1–30 in System Settings. A missing, invalid, or unavailable setting falls back to two. Holidays are not excluded. The stored due date uses the existing Task date-only convention of noon UTC. The Task starts Open with Normal priority. Its title uses company, then contact name, then a generic fallback. The description contains only available Trade Show, lead, company, email, and product-interest context. The Task links to its source Lead, and to an existing Account and Contact where linked. The Task detail page links back to the Trade Show Lead.

The `source` marker `TRADE_SHOW_LEAD_FOLLOW_UP` and `tradeShowLeadId` identify automated Tasks. A partial unique index limits each lead to one active auto Task. Reassignment moves an open Task to the new rep and records an assignment event while keeping its due date, priority, notes, and original assignee. If that Task is Completed or Cancelled, the new assignment creates a fresh Task using the current setting and retains the resolved one. Changing the setting never updates existing Tasks, including rep-edited due dates. Unassignment or routing away from BIXOLON Sales changes an open auto Task to Cancelled. Manual Tasks are untouched. Task completion creates no Activity and changes no lead status.

An ineligible Task assignee or Task write error fails the enclosing transaction and is reported to the caller. The lead assignment therefore does not commit without the required Task. Assignment eligibility uses the standard `tasks.write` rule; Task visibility and edits use the normal Tasks workflow. A deliberate Admin backfill could be built later but is not part of this migration.

Partner routing uses the separate [Partner Handoffs workflow](trade-show-partner-handoff-v1.md). Assigning a partner adds leads to Awaiting Handoff. Export & Complete Handoff marks the leads as Sent to Partner and creates one internal follow-up Task for the handoff, linked to the Partner Account. Select the Follow-up Owner during partner routing; that user receives the eventual Task and is shown by name in Partner Handoffs. Legacy assignments without a selected owner retain the existing event Marketing Owner / handoff user resolution. An unavailable explicit owner must be replaced before completing the handoff; the system does not silently substitute another user. The same configured business-day setting applies. Use View Partner Handoff on the Task to open the completed handoff. Re-export Handoff creates no additional Task. Existing internal routing behavior described above is unchanged.
